Git

معرفی خودتان به Git

git config

یک بار برای همیشه به Git می‌گویید شما کی هستید. اسم و ایمیل شما روی هر commit ثبت می‌شود.

  • user.name اسم شما
  • user.email ایمیل شما (بهتر است همان ایمیل GitHub باشد)
  • init.defaultBranch main نام شاخه‌ی اصلی را main می‌گذارد
نکته --global یعنی این تنظیم برای همه‌ی پروژه‌های این کامپیوتر است؛ پس فقط یک بار لازم است.
Git Bash

شاخه: یک مسیر موازی

git branch

می‌خواهیم برای سایت تم تیره بسازیم، ولی نسخه‌ی اصلی دست نخورد. پس یک شاخه (branch) جدا می‌سازیم.

  • git branch فهرست شاخه‌ها؛ ستاره * یعنی الان کجایید
  • git branch dark-theme یک شاخه‌ی جدید می‌سازد
  • git branch -d dark-theme شاخه را پاک می‌کند
نکته ساختن شاخه یعنی فقط ساختن؛ هنوز روی main هستیم!

یکی کردن شاخه‌ها

git merge

تم تیره آماده است. حالا تغییرات dark-theme را به main می‌آوریم. اول به شاخه‌ی مقصد بروید، بعد merge کنید.

  • بعد از merge می‌توانیم شاخه را پاک کنیم

فرستادن به GitHub

git push

خبر گرفتن از GitHub

git fetch

به‌روز کردن پروژه

git pull

git pull تغییرات GitHub را می‌گیرد و با کار ما یکی می‌کند. در واقع یعنی fetch + merge.

git pull = git fetch + git merge
  • حالا README ما هم لینک دمو را دارد
  • اگر هر دو نفر همان خط را عوض کرده باشند، اینجا هم ممکن است conflict پیش بیاید
نکته عادت خوب: شروع کار ← git pull، پایان کار ← git push.

برگرداندن اشتباه‌ها

git restore / git revert
چه شده؟چه کنیم؟
فایل را خراب کردم، هنوز add نکرده‌امgit restore style.css
add کردم ولی پشیمانمgit restore --staged style.css
commit کردم و می‌خواهم برگردمgit revert <hash>
⚠️ git restore تغییرات ذخیره‌نشده را برای همیشه پاک می‌کند.
نکته revert چیزی را از تاریخچه پاک نمی‌کند؛ یک commit جدید می‌سازد که برعکسِ قبلی است. --no-edit یعنی پنجره‌ی ویرایش پیام باز نشود.

کشوی موقت

git stash

وسط ساختن لینک ایمیل در footer هستیم که می‌گویند «فوری متن README را درست کن!». کار نیمه‌تمام را در کشو می‌گذاریم.

  • git stash تغییرات را کنار می‌گذارد و پوشه تمیز می‌شود
  • git stash list محتوای کشو را نشان می‌دهد
  • git stash pop تغییرات را برمی‌گرداند
نکته stash برای مدت کوتاه است؛ کار را زیاد در کشو نگه ندارید.
